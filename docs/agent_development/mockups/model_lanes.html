Who does what — three lanesThe guard enforces tiers in code whichever model runs; the lane only decides which model does the language work.

Local only free · offline

Data is inside the app’s DB, the task is simple, and the result is checked by code or lands in a branch.
Shipment instruction → typed parameters (builder runs in code)
“Set niche profit 25 %, wholesaler cap 1,200” → value edits in a branch
Wording a finished result from its facts
Shrinking big tool results before the planner sees them
Routing: read / simulate / write
RAG reports, titles, daily summary of moved metrics

API only (Claude) strongest model

Open-ended, outside the DB, risky, or untrusted input.
Planning across many tools; choosing the tools
Web search, DIAN / Comtrade orchestration, source refresh
Anything that reads documents or web pages (prompt-injection risk)
Ambiguous requests, trade-off analysis, optimising scenarios
Merging a branch: conflicts and the change-set wording
Sensitive actions (only with explicit confirmation)

Local drafts · API checks cheap + safe

Local does the bulk; a short API call confirms before it matters.
Shipment/route edits that will be proposed to live data
Batch edits to many values in a branch before they are merged
Product → tariff line / HS suggestions in “review” cases
Values extracted from a document (each with its quote)
The user-facing daily/weekly report (sampled)
The “local drafts, API checks” protocol
User instruction→ Local model: typed draft (JSON schema)→ Code: validate + run engine + preview numbers→ API check: instruction + draft + preview → approve / reject + reason→ You: Apply / Discard
Failure paths: validation fails→API does the job itself API rejects→API redoes it; the disagreement is logged still unclear→asks you
